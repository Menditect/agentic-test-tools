# Menditect Agent Workspace Template - Release Notes

## Version v1.3.2

> Released on: 2026-09-10

### Release Summary
Improved mta_config file. Adheres strictly to the canonical configuration specification (docs/mta-config-reference.md) and JSON Schema (mta_config.schema.json). Injects $schema into generated configuration files, sanitizes app_instances to eliminate null fields, deploys the schema alongside mta_config.json in external workspaces, introduces defensive key aliasing across all consumers, and expands the verification suite (npm run verify) with schema validation and mxcli binary execution readiness checks.

---

### Detailed Changes

#### 1. Configuration Schema Integration & Strictness (mta_config.schema.json)
- Added `$schema` property definition to the canonical schema properties.
- Strictly validates required top-level properties (`mta_base_url`, `mcp_endpoint`), property types, and structure of `app_instances`.

#### 2. Setup Wizard Improvements (scripts/setup.js)
- **Automatic Schema Reference**:
  - Automatically writes `"$schema": "./mta_config.schema.json"` into newly generated or updated `mta_config.json` files for instant IDE code completion and linting.
- **App Instance Sanitization**:
  - Sanitizes `app_instances[]` records to write only populated string values, completely omitting unset optional fields (`mtaUrl`, `runtimeUrl`, `pluginUrl`, `pluginToken`, `pluginPort`) instead of outputting `null`.
- **Target Workspace Schema Deployment**:
  - When configuring workspaces outside clone root (Mendix Project or Custom Directory), `mta_config.schema.json` is automatically copied alongside `mta_config.json` to enable local schema resolution.
- **Defensive Input Aliasing**:
  - Uses `normalizeConfigAliases()` to read and resolve existing configuration files containing legacy keys (`mpr_path`, `project_dir`, `mta_url`, `instance_token`).

#### 3. Defensive Key Aliasing (scripts/setup.js, scripts/mta-proxy.js, scripts/sync-upstream.js, scripts/verify-setup.js)
- Standardized configuration resolution across all repository scripts:
  - `mendix_mpr_path` <- `mpr_path`, `mprPath`
  - `mendix_project_dir` <- `project_dir`, `projectDir`
  - `mta_base_url` <- `mta_url`, `mtaUrl`
  - `default_app_instance_token` <- `app_instances[0].token`, `instance_token`
  - `execution_plans_dir` <- `${mta_output_path}/execution-plans`
  - `execution_plans_archive_dir` <- `${execution_plans_dir}/archive`
  - `plugin_mcp_url` <- `plugin_url`, `pluginUrl`

#### 4. Expanded Preflight Verification (scripts/verify-setup.js)
- **Schema Compliance Diagnostic**:
  - Validates `mta_config.json` against `mta_config.schema.json` and reports any missing required properties, invalid types, or malformed instance entries.
- **Model Tooling Readiness**:
  - Probes the `bin/mxcli.exe` binary and executes `--version` to verify execution permissions and operational readiness.

#### 5. Documentation & Contract Reference (docs/mta-config-reference.md, README.md)
- Integrated the full MTA Configuration Specification (`docs/mta-config-reference.md`) defining the single source of truth (SSOT) data contract, property dictionary, resolution order, and aliasing matrix.
- Updated `README.md` to reference the configuration specification and JSON schema in the setup workflow and directory structure.

---

### Upgrading / Migration Notes
To upgrade an existing workspace to v1.3.2:
```bash
git pull origin main
npm run setup
npm run verify
```
*(or `.\setup.ps1` followed by `npm run verify` on Windows)*

Running `npm run setup` will re-save your `mta_config.json` with the schema declaration and sanitized instance fields. Running `npm run verify` will check schema compliance and tool readiness.
