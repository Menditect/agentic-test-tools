# Menditect Agent Workspace Template - Release Notes

## Version v1.6.2

> Released on: 2026-09-16

### Release Summary
improved mta_config settings

---

### Detailed Changes
- **Eliminated Hardcoded Token & Property Scaffolding from Agent Directives**:
  - Removed static application names, MTA URLs, and application instance token mappings from `# Menditect Architecture Setup` sections in `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, and `.github/copilot-instructions.md`.
  - Prevented stale or invalid tokens in assistant context windows from overriding dynamically resolved configuration.
- **Enforced `mta_config.json` as Single Source of Truth (SSOT)**:
  - Standardized root directives across all supported AI assistants to command dynamic loading of all environment properties (`application_name`, `mta_base_url`, `default_app_instance`, `default_app_instance_token`, `app_instances[]`) directly from `mta_config.json`.
- **Scaffolding & Directives Automation Alignment**:
  - Updated `scripts/setup.js` and `scripts/sync-upstream.js` (`getMenditectSetupBlock`) to generate clean, dynamic SSOT directives.
  - Updated `npm run setup:directives` (`scripts/setup.js --directives-only`) to restore the clean SSOT connection block without hardcoding credentials or instance lists.
- **Verification Integrity Updates**:
  - Updated `scripts/verify-setup.js` (`npm run verify`) to validate `# Menditect Architecture Setup` and `ENVIRONMENT SSOT` integrity across all directive files.
- **Documentation Updates**:
  - Updated `README.md` to clarify the dynamic SSOT resolution architecture.

---

### Upgrading / Migration Notes
No breaking changes. Run `npm run setup:directives` to immediately update existing workspace directive files (`AGENTS.md`, `CLAUDE.md`, `GEMINI.md`) to the clean SSOT directive structure.
