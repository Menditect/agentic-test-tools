# Menditect Agent Workspace Template - Release Notes

## Version v1.2.0

> Released on: 2026-09-09

### Release Summary
Support for different workspace configurations. Introduces a 3-way workspace selection model (Dedicated Tools Workspace, Direct Mendix Project Workspace, or Custom Directory), native Mendix 11.12+ module skills integration via automatic binary .mpr version inspection, alignment of execution plan storage with the official Menditect skills convention (menditect-output/execution-plans/ and archive/), non-destructive IDE configuration merging, pre-selection file placement breakdowns with Mendix Git impact notifications, and official vibe-coding and community support disclaimers.

---

### Detailed Changes

#### 1. Multi-Workspace Architecture (scripts/setup.js)
- **Three-Way Workspace Selection**:
  - **Option 1: Dedicated Tools Workspace (Clone Root)**: Operates entirely inside the agentic-test-tools clone directory. All skills, runners, and configs stay isolated. Zero changes or files are introduced into the Mendix project repository.
  - **Option 2: Direct Mendix Project Workspace**: Configures the Mendix project root folder directly as the IDE workspace. AI agents gain direct access to the Mendix domain model, microflows, and project files.
  - **Option 3: Custom Directory**: Allows specifying an arbitrary external directory to host the agent workspace.
- **Pre-Selection File Breakdown & Git Impact Notice**:
  - The setup wizard now displays a clear breakdown of which files will be placed where *before* asking the user to choose an option.
  - Explicitly warns users choosing Option 2 that files placed in the Mendix project directory (skills, ./mxcli wrappers, execution plan folders, IDE settings) will be tracked and committed to that Mendix project's Git repository.

#### 2. Native Mendix 11.12+ Module-Level Skills Support
- **Automatic Binary .mpr Version Detection**:
  - `detectMendixVersion` directly parses the header signature of the project's binary .mpr database file without requiring external tooling or Studio Pro to be open.
- **Version Gating (11.12+)**:
  - Only Mendix 11.12 and higher supports module-level skills (`skillssource/_modules/menditect_agentictestskills`).
  - If Mendix 11.12+ is detected and the Marketplace module is present, skills are installed directly inside `skillssource/_modules/menditect_agentictestskills/`.
  - If Mendix is below 11.12 or the module is not yet installed, the wizard falls back to project-level skills (`./skills/`), ensuring complete backward compatibility.
- **Project-Level AGENTS.md Directives**:
  - For module-level skills, appends a dedicated directive block commanding AI agents to autonomously explore and load `[Menditect_AgenticTestSkills]` without asking permission.
  - Preserves any existing project-level directives, rules, or instructions.

#### 3. Execution Plan Storage Alignment (menditect-output/)
- **Full Alignment with mta-ai-assistant Standards**:
  - Aligned local plan paths with the official MTA skill specifications (`PAT-43`, `PAT-44`, `PAT-47`).
  - Active execution plans are saved to:
    `${MTA_OUTPUT_PATH}/execution-plans/EP_<TestCaseName>.md` (defaulting to `${workspaceFolder}/menditect-output/execution-plans/EP_<TestCaseName>.md`).
  - Superseded plans are archived to:
    `${MTA_OUTPUT_PATH}/execution-plans/archive/EP_<TestCaseName>_<timestamp>.md`.
- **Environment Variable Injection**:
  - Setup now injects `MTA_OUTPUT_PATH="${workspaceFolder}/menditect-output"` into `.vscode/settings.json`, `.env`, and `mta_config.json`.
  - Automatically provisions both the active `execution-plans/` and historical `archive/` subdirectories during workspace initialization and synchronization.

#### 4. Non-Destructive IDE Configuration Merging
- **Preserves Existing Settings and Permissions**:
  - Replaced destructive overwrite logic with a non-destructive `mergeJsonFile` updater.
  - Existing tool permissions (such as `Bash(mxcli:*)` in `.claude/settings.json`) and existing custom MCP servers in `.vscode/mcp.json` or `.cursor/mcp.json` are retained and cleanly merged.
  - Terminal environment variables across Windows, Linux, and macOS platforms are merged seamlessly.

#### 5. Upstream Synchronization & Migration (scripts/sync-upstream.js)
- **Workspace-Aware Syncing**:
  - Reads `mta_config.json` to resolve the active workspace directory, binary destination, and skills target.
- **Automatic Marketplace Module Migration**:
  - When running `npm run update:skills` on a project where the `Menditect_AgenticTestSkills` module has subsequently been imported, automatically offers migration from `./skills/` to `skillssource/_modules/menditect_agentictestskills/` and updates project directives.
- **Multi-Path Config Resolution in Proxy (scripts/mta-proxy.js)**:
  - Supports locating `mta_config.json` via environment variables, tools root directory, or current working directory.

#### 6. Vibe-Coding Notice & Community Support Disclaimer
- **README.md**:
  - Added a prominent `[!WARNING]` callout near the top of `README.md` and a formal **Disclaimer & Support Policy** section.
  - Clarifies that this repository is vibe-coded using AI coding assistants and provided strictly "AS IS".
  - States clearly that Menditect B.V. provides no official commercial support, SLAs, or guarantees, and disclaims liability for damages or data loss in accordance with the Apache License 2.0.
  - Advises best safety practices: committing to Git before running tools, avoiding running `mxcli` while a project is open in Studio Pro, and auditing generated tests.
- **Interactive Setup Wizard (scripts/setup.js)**:
  - Added an interactive disclaimer banner at launch requiring explicit user acknowledgment before continuing.

### Upgrading / Migration Notes
To upgrade an existing workspace to v1.2.0:
```bash
git pull origin main
npm run setup
```
*(or `.\setup.ps1` on Windows)*

Choose your preferred workspace option (Option 1, 2, or 3) and verify that your `menditect-output/` and IDE configurations are updated accordingly.
