# Menditect Agent Workspace Template - Release Notes

## Version v1.3.1

> Released on: 2026-09-10

### Release Summary
Improved setup of configuration. Introduces configuration-scoped resolution of MTA connection URLs, runtime URLs, and plugin tokens from Mendix Studio Pro profiles, flexible discovered instance selection supporting comma-separated numbers and ranges, automatic derivation of the MTA plugin MCP endpoint from the configuration's runtime URL, and extraction of the plugin MCP access token from configuration constants.

---

### Detailed Changes

#### 1. Configuration-Scoped MTA Settings Resolution (scripts/setup.js)
- **Profile-Scoped Constants Extraction**:
  - Previously, connection URLs were matched globally from the first occurrence in the project model settings, which could cause a local instance to receive a cloud URL defined in an unrelated configuration.
  - The setup wizard now scopes all constants and runtime settings directly under each Studio Pro configuration profile (`alter settings constant ... in configuration '<name>'` and `create or modify configuration '<name>'`).
  - Profiles now independently maintain their own:
    - `token`: Discovered `MtaPluginModule.ApplicationInstanceToken`.
    - `mtaUrl`: Discovered `MtaPluginModule.MTAConnectionUrl` (with WebSocket `wss://` / `ws://` converted to `https://` / `http://`).
    - `runtimeUrl`: Extracted `ApplicationRootUrl` from the configuration block.
    - `pluginUrl`: Formed directly from `<runtimeUrl>/plugin/mcp`.
    - `pluginToken`: Extracted from `MtaPluginModule.McpServerAccessToken` and formatted with the `Bearer ` prefix.
    - `pluginPort`: Local runtime port (`HttpPortNumber` or derived from `ApplicationRootUrl`).

#### 2. Flexible Discovered Instance Selection (scripts/setup.js)
- **Selection Flexibility**:
  - Replaced the binary confirmation prompt with a flexible selector:
    - `all` (or Enter / `y`): Imports all discovered configurations.
    - Comma-separated numbers or ranges (e.g. `6`, `1, 3, 6`, or `1-3, 6`): Imports only the selected configurations.
    - `none` (or `n`): Skips discovered instances and drops into manual configuration.
- **Smart Active Default Handling**:
  - If exactly 1 instance is selected, it is automatically assigned as the active default instance without requiring an extra prompt.
  - If multiple instances are selected, the wizard displays the chosen subset and prompts the user to select the active default from that subset.
  - Robust bounds checking and validation re-prompts on invalid inputs.

#### 3. Runtime URL Integration for MTA Plugin Endpoint (scripts/setup.js)
- **Dynamic Plugin Endpoint Derivation**:
  - Extracted `ApplicationRootUrl` from the chosen Mendix Studio Pro configuration to dynamically construct the MTA Plugin MCP endpoint (`<runtimeUrl>/plugin/mcp`).
  - Supports both local endpoints (e.g. `http://localhost:8081/plugin/mcp`) and custom or remote environments (e.g. `https://myapp.mendixcloud.com/plugin/mcp`).

#### 4. Automated Plugin Bearer Token Discovery (scripts/setup.js)
- **McpServerAccessToken Constant Support**:
  - Automatically reads the `MtaPluginModule.McpServerAccessToken` constant defined for the chosen configuration.
  - Pre-fills the `App under test Plugin Token` prompt with the formatted Bearer token (e.g. `Bearer 1`).

#### 5. Documentation Updates (README.md)
- Updated setup wizard documentation to describe configuration-scoped settings discovery, flexible instance selection syntax, runtime URL integration, and plugin token constant extraction.

### Upgrading / Migration Notes
To upgrade an existing workspace to v1.3.1:
```bash
git pull origin main
npm run setup
```
*(or `.\setup.ps1` on Windows)*

Running `npm run setup` allows you to pick specific application instances and automatically inherit the connection URL, runtime URL, and plugin token belonging to your chosen configuration.
