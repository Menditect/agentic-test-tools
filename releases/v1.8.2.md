# Menditect Agent Workspace Template - Release Notes

## Version v1.8.2

> Released on: 2026-09-25

### Release Summary
fixed error in authentication header and force native mcp execution

---

### Detailed Changes
- **MTA Identification Token Normalization (`formatAuthHeader`)**: Fixed string concatenation bug in `scripts/setup.js` ensuring identification tokens (e.g., `menditect_mta_identification_token<key>`) are formatted with a clean single space (`Bearer menditect_mta_identification_token <key>`), preventing HTTP 401 Unauthorized errors during IDE MCP initialization.
- **Defensive Header Normalization in `mta-proxy.js`**: Added runtime normalization in `sendHttp()` so manual `.env` edits or cached tokens missing the separating space are dynamically formatted before forwarding to upstream MCP servers.
- **Deprecated CLI Bridge Scripts**: Confirmed complete deprecation and removal of `mta-client.js` from templates to prevent agents from relying on subprocess bridges.
- **Native MCP Execution Mandate**: Added strict directives to `AGENTS.md`, `GEMINI.md`, `CLAUDE.md`, `.github/copilot-instructions.md`, and the setup generator (`getMenditectSetupBlock`) mandating native IDE MCP tool execution (`call_mcp_tool`, `mta`, `mta_plugin`, `execute-testcase`) and prohibiting ad-hoc runner scripts (`build-*.js`, `run-*.js`).
- **Enhanced `.env.template`**: Added detailed comments, configuration context, and verified syntax examples for `MTA_MCP_ENDPOINT` and `MTA_MCP_AUTH_HEADER`.

---

### Upgrading / Migration Notes
No breaking changes. Run `npm run verify` to confirm your workspace environment configuration and token formatting.
