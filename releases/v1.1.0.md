# Menditect Agent Workspace Template - Release Notes

## Version v1.1.0

> Released on: 2026-09-08

### Release Summary
Configured automated project-level agent directive settings across AGENTS.md, CLAUDE.md, GEMINI.md, and .github/copilot-instructions.md. Automatically derives the Mendix Application Name from the .mpr project file, persists it across all configuration files, and establishes project-level operational rules for AI agents.

---

### Detailed Changes

#### 1. Automated Application Name Resolution
- **Automatic .mpr Filename Extraction**:
  - The setup wizard (`scripts/setup.js`) now extracts the base application name directly from the discovered `.mpr` project file (for example, `OrderManagement.mpr` automatically yields `OrderManagement`).
  - Presents the derived name as the default in the interactive setup prompt, allowing one-key acceptance or custom override.
  - Falls back gracefully to the project directory name when using Studio Pro MCP mode or if no `.mpr` file is present in the workspace.

#### 2. Cross-Agent Directive Synchronization
- **Standardized Architecture Setup Block**:
  - Automatically provisions the `# Menditect Architecture Setup` section into all supported agent instruction files:
    - `AGENTS.md` (universal standard for Cursor, Cline, and agentic tools)
    - `CLAUDE.md` (Claude Code)
    - `GEMINI.md` (Gemini and Antigravity)
    - `.github/copilot-instructions.md` (GitHub Copilot and Codex)
  - Injects the active Application Name and MTA URL directly into the directive block:
    ```markdown
    # Menditect Architecture Setup
    - **CRITICAL OPERATIONAL COMMAND:** Always execute tasks using the core rules defined in: [skills/AGENTS.md].
    - **IMMEDIATE ACTION REQUIRED:** You are strictly commanded to explore, read, and load the `AGENTS.md` and context of the `skills/` directory before answering any user prompt.
    - ** Application name is: <ApplicationName> **
    - ** MTA Url: <MtaUrl> **
    ```
  - Directs AI agents to immediately load and respect Menditect's test automation skills before attempting to construct tests or diagnose failures.

#### 3. Idempotent In-Place Updating
- **Duplicate Prevention**:
  - The directive updater parses each directive file for existing `# Menditect Architecture Setup` sections.
  - If already present, it updates the section in-place with the latest configuration values.
  - If missing, it appends the section cleanly to the bottom of the file.
  - Safe to run repeatedly during project re-configurations without creating duplicate blocks or conflicting headers.

#### 4. Unified Configuration Persistence
- **mta_config.json**:
  - Added `"application_name"` to the primary configuration schema.
- **Environment Variables (.env)**:
  - Added `MENDIX_APP_NAME` alongside existing MCP and project path definitions.
- **VS Code Environment Settings (.vscode/settings.json)**:
  - Added `"MENDIX_APP_NAME"` to terminal environment settings across Windows, macOS, and Linux profiles.
  - Fixed a variable reference ensuring `MTA_BASE_URL` correctly resolves the configured MTA instance URL.

#### 5. Documentation and Repository Templates
- **Template Directives**:
  - Updated repository template directive files (`AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, `.github/copilot-instructions.md`) to include the default `# Menditect Architecture Setup` structure with clear placeholders for fresh repository clones.
- **README.md**:
  - Updated the setup guide in `README.md` to reflect the automatic derivation of the Application Name and automated directive generation.

---

### Upgrading / Migration Notes
Existing workspaces can adopt these improvements by running:
```bash
npm run setup
```
*(or `.\setup.ps1` on Windows)*

The wizard will detect your project, prompt for the Application Name with the `.mpr` name pre-filled, and automatically populate all configuration files and agent directives. No manual file editing is required.
